# EgoEngine RL 复现：当前情况与待讨论问题

更新时间：2026-09-17。以下区分论文内容、项目实测和未解决的问题；请不要把
接口测试、碰撞壳重叠或局部姿态测试当作 Pour 任务成功。

## 1. 输入、目标和已经确定的边界

目标是实现 EgoEngine 第 3.2 节和附录 C 的机器人动作生成/RL 部分，不做最终
视觉策略训练。用户决定不复现闭源 MPC，使用 **Replay → 残差 PPO**，因此不是
原论文三模式流程的完全复现，也不能直接声称计算成本与原论文可比。

当前只推进 TACO `(pour in some, bowl, plate)/20230927_017`：右手操作碗，左手
支撑盘子。碗是 tool，盘子是 target，名称表示任务角色，不表示两者固定不动。
样本有 198 帧双手 MANO/关节点 GT、两个物体的位姿 GT、网格、相机参数、RGB
和原始 16 位深度。RGB/GT 为 30 Hz；机器人参考有 198 个状态、197 个控制间隔。
这是用户批准的 GT 输入验证，不复现从视频估计姿态的误差，也没有证据说明
该编号就是作者使用的示范。

输入关系：真人手 GT → **MINK 重定向** → XHand 机器人参考；RL 读取机器人
参考、物体目标轨迹、仿真当前状态和明确的初始状态。RGB/深度用于审查，
不是当前 actor 的观测。当前没有用 SPIDER 替代 MINK 做正式重定向；复用了
SPIDER/MJWP 仿真相关代码，并连接了 Human2Sim2Robot 的 PPO 训练代码。

双手从一开始就支持；两个物体在执行时都是被动物体，不能用控制器强行贴住 GT。
模型 qpos 50 维、qvel 48 维、手部控制 36 维。保留全部源帧，不用裁掉失败段、
移动 GT、放宽关节限位或改评价阈值掩盖问题。旧的单样本首帧手动可行化诊断
没有被采用为正式初始化，也未证明能跨任务有效。

## 2. 已清理的错误结论

“碰撞壳”是仿真中用于碰撞判断的简化形状，可能把原始 CAD 的凹槽填满。
**外壳相交，不等于原始部件实体相交；清除误报分类，也不等于修好了这个外壳。**

| 记录 | 当前正确解释 |
| --- | --- |
| Pour 首帧左右手掌—食指根部 | 原始闭合实体没有交集，碰撞壳重叠属于误报；从“首帧真实穿透”结论中剔除。 |
| 第 93、177 行两处“漏检” | 实际分别生成 3、4 个接触，最大壳重叠 0.03915、0.02425 mm；只是小于 0.05 mm 报告统计档位，不是漏检。 |
| 中立姿态误报降到右/左 2.25/1.46 mm | 只是一对部件的形状实验，不是整个首帧误差，也不是合法初始化结果。 |
| FCL 报告原始三角面相交 | 可能是贴合、装配重叠或真实穿透，不能仅凭该布尔值一律判非法；不相交也不能排除完整包含。 |

报告代码已将外壳重叠、原始实体证据和运行时接触分开；没有删除需要的物理
碰撞对，也没有对整对部件永久免检。原始记录仍保留供复查。

## 3. 当前确实还存在的问题

### 首帧不合法

在**现行坐标变换和 z=0.72 m 的仿真桌面**下：

- 右手原始网格最低点进入桌面约 **20.79 mm**，在拇指末节。
- 左手原始网格最低点进入桌面约 **9.65 mm**，也在拇指末节。
- 左掌与拇指部件原始实体交集约 **9.25 mm³**，这是体积，不是穿透深度。
- 手与盘子另有壳重叠/表面交叉证据；不能把壳的距离直接称为原始网格穿透深度。

所以：原始首帧不能直接作为正式 RL 初始状态。这些数值证明的是当前仿真
模型不自洽，不是证明现实中的真人手穿入了真实桌子。

### 桌面与原始数据还未完全对齐

EgoEngine 附录 A.1（PDF 第 15 页）确实规定桌高 **0.72 m**，对应作者的
机器人工作台；它不是 TACO 世界坐标中的真实桌高。当前把盘子首帧网格最低点
对齐到 0.72 m 的竖直平移，是本项目做法，完整转换方法不是论文公开参数。

原始深度确实有绝对尺度：`depth_m = raw_uint16 / 4000`，分辨率 1920×1080。
按当前相机参数、同帧号配对和统一变换，桌面拟合代表高度约 **0.7365 m**，
比仿真桌面高 16.5 mm，平面绝对残差中位数/P95 约 3.63/14.83 mm。
碗和盘子的 GT 底面分别低于该拟合面约 15.78/22.21 mm。

深度 AVI 容器标记 15 fps，但有同样的 198 帧；直接同帧号配对比按 2 倍帧号
配对更一致。缺少采集时间戳，仍不能宣称严格同步已证明。GT 网格轮廓与 RGB
大体吻合；深度与 GT 表面偏差在物体、人手上方向不同，单一深度常数偏移不足
以解释。传感器配准、材质误差、网格与实物差异及标注误差尚未分离。

已验证统一变换的导出计算一致，24 个手部关节的原点、轴、范围与源 URDF
一致；这些检查不等于证明原始传感器标定准确。尚未改桌高或 GT。

### 碰撞模型还需处理的部分

左右掌部—食指根部在中立姿态和首帧没有原始实体重叠，但在侧摆 **+0.175 rad**
时都有真实重叠：交集约 **196.1 mm³**，最大采样穿入约 **2.97 mm**，交叉点
可离转轴约 34.6 mm，不只是轴承贴合。当前参考右手第 45 行、左手第 13 行
已经到达这个角度（零起始行号）。所以不能将这对部件整体豁免。

形状实验：将食指根部由 1 块改成 32 块，误报几乎不变；继续细分手掌、只从
碰撞壳中移除经原始 CAD 证实为空的局部槽，仍有中立姿态右/左 2.25/1.46 mm
误报。因此新形状没有被采用。不能靠缩小原始实体来换取检查通过。

MINK 过去会忽略显式指定的父子部件对，此代码问题已修复并测试；但上述
掌部—食指碰撞对尚未在选定模型中启用，避免把已知假障碍交给求解器。
其他关节处的源 CAD 装配重叠还需按局部位置区分，不能全部判非法或全部豁免。

细化候选盘子的最大采样向外偏差约 **1.615 mm**；198 帧中 8773 个活动对
最近点的最大偏差约 **0.998 mm**。这是有限采样，既不是全局保证，也不是
论文给定的验收阈值。目前不打算为追求全局零误差盲目增加所有凸块。

## 4. Replay → RL 到哪一步了

- 已实现论文对应的奖励/评价公式和 **20 步一块、前瞻 40 步、仅提交前 20 步**
  的调度；失败后从同一物理边界进入 PPO，而不是偷偷重置为理想参考姿态。
- 真实 GPU 接口测试已跑通 PPO 回退、保存/恢复和 40/20 调度。测试使用受控
  场景或人为触发回退，不是 Pour 任务成功实验。
- 细化候选在 4/16 个 GPU 世界、198 帧及短时压力检查中，通过每世界 1024
  接触容量/2048 约束容量检查；旧的 128/512 曾溢出。正式配置尚未换到候选，
  正式启用时必须同步容量。该测试不保证未来所有 RL 姿态，也不证明合法初始化。
- **尚未采用合法初始化，尚未运行正式 Pour Replay→RL；没有证明 XHand 稳定
  抓住了碗/盘，也没有证据说明残差 RL 已修正上述误差。**

Pour/Bowl/Plate 的位置 0.12 m、旋转 1.5 rad 是附录 C.2 给出的任务示例阈值，
不是允许手指穿透的阈值。TACO 全部奖励系数、两种误差如何组合成边界 C、
物理初始化细节并未完全公开。当前适配器的临时系数/组合办法必须标为本地
设置，不能反称作者配置。用户已同意分别报告碗单物体、碗+盘双物体扩展结果。

现已从架构上隔离这两类 objective：正式入口不指定 profile 时请求论文配置，
由于 `lambda_p/lambda_R/C/contact coefficient` 未公开而直接拒绝；工程调试只能
显式选择 `taco_pour_local_unpublished_v1`。该 profile 固定记录全部数值、来源和
文件 hash，但 protocol 仍将其 `run_ready` 设为 false，不能借此绕过初始化、
碰撞模型和 observation gate。PPO YAML 中原先会静默生效的阈值和系数已删除。

双物体扩展继续采用“两个 tracking reward 取平均、任一物体越界即终止”，但
已从隐式代码行为提升为 profile 协议。每一步会分别保存 bowl/plate 的位置、
旋转、组合误差、reward、终止标志，以及左右手对每个物体的 contact bonus，
并指出第一个失败的 endpoint 和物体，不再只留一个平均误差。

初始化 gate 也不再只看 `qpos/qvel/ctrl` 的形状。正式 artifact 必须声明手和
物体的 qpos/qvel 来源、ctrl 来源、第一条命令、临时固定方法、释放时刻和释放后
被动物理验证；报告必须与 artifact 元数据逐项一致，正式 XML 不能残留 hold
约束。release validation 还必须绑定统一的 physics contract：完整 PPO config、
scene XML、92 个外部 mesh、MJWP 时间步/容量、依赖版本及应用 Spider solver/contact
覆盖后的编译模型签名；正式环境创建后会再次核对实际模型签名。当前尚无 Pour
artifact 满足此 schema，因此仍没有运行正式 40 步窗口。

本地 objective 的 `lift.object_role: tool` 已进入 runtime type contract，会按
场景的命名角色选择物体，不再硬编码第 0 个物体。逐步 trace 也新增
`aggregate_tracking_reward / aggregate_contact_bonus / lift_reward`，现在可以逐项
复算 `total_reward`。

另一个独立 blocker 是 236 维 actor observation 的具体编码属于本地实现。
物体 goal 在 transition 前用 `t` 还是 `t+1` 尚未批准修改；当前代码保持 `t`，
本次没有改 PPO 或 observation indexing。

## 5. 请网页版帮助讨论的具体问题

请优先依据 EgoEngine 原文、MuJoCo/XHand 官方模型和相关论文/开源实现，
区分有文献支持的做法与针对本项目的新提案，不要直接假设代码无错或先调权重。

1. 对掌部—食指根部这种“零姿态壳误报、其他姿态原始 CAD 真干涉”的连接件，
   如何构造适合 MuJoCo 且 MINK 使用一致规则的碰撞形状？怎样区分合法装配
   接触和需要阻止的外部干涉，避免删碰撞对、无限增加分块或改关节范围掩盖问题？
2. 在深度承载面、物体 GT、机器人参考不完全一致时，哪些检查应优先做，
   哪些量应固定，怎样避免错误地把标定误差全部归因于重定向？
3. 在同一经过检查的模型上，怎样公平比较“无碰撞操作前姿态”和“固定物体
   下的物理修正重定向”，同时明确 qpos、qvel、首条控制、参考起点和释放
   被动物体的步骤？既保留全部源帧，也不要求机器人在开始时就已经抓稳。
4. 怎样用尽量少且清楚的检查允许进入首个 40 步 Replay→RL 窗口，避免把
   “全轨迹已成功”当作 RL 前提，也避免用 RL 掩盖碰撞模型/初始状态缺陷？

两种初始化候选的方法线索分别来自
[Human2Sim2Robot 附录 B](https://arxiv.org/html/2504.12609v1#A2) 和
[DexMachina 附录 A.2](https://arxiv.org/html/2505.24853v1#A1.SS2)。它们不是
EgoEngine 已公开的 XHand/TACO reset 配方，也没有提供本项目应照抄的数值。
当前仅批准比较，尚未运行正式对照或选择一种作为通用链路。
