# Pour 原始深度与桌面检查

检查对象是 Pour/Bowl/Plate `20230927_017` 的 198 帧原始 16 位深度、
RGB、相机参数、物体 GT 和 MANO GT。深度严格按
`depth_m = raw_uint16 / 4000.0` 解码。本检查没有改桌面、GT、统一坐标变换、
机器人初始姿态或碰撞模型。

## 结论

原始深度确实是有绝对尺度的米制深度。此前“没有 metric depth”的说法只适用于
当时本地仅有的有损缩放视频，不适用于现在已经下载的原始 `gray16le` 文件。

它能在当前相机参数和帧号配对假设下恢复出稳定的蓝色承载面，但这个面与发布
物体 GT、当前仿真桌面不完全吻合。已确认没有漏做 `raw/4000`；暂未发现明显的
外参方向错误，但尚未完成深度/RGB 的严格时空标定，不能宣称所有坐标问题已排除。
因此，不能把桌面直接改成 `0.7365 m` 就认定完成修复。

`0.72 m` 有明确论文依据：EgoEngine 附录 A.1（PDF 第 15 页）规定此桌面高度，
并说明与作者真实机器人工作台一致。它不是 TACO 世界坐标的桌面真值。

## 桌面测量

同帧号配对的全序列拟合结果为：

| 项目 | 结果 |
| --- | ---: |
| TACO 世界中的承载面高度（代表位置） | `0.56556 m` |
| 应用当前 `T_sim_world` 后的高度 | `0.73650 m` |
| 相对作者工作台设定 `0.72 m` | `+16.50 mm` |
| 拟合平面倾斜 | `1.89 deg` |
| 全局绝对残差中位数 / P95 | `3.63 / 14.83 mm` |

逐帧独立拟合后，在同一个世界 XY 位置，P1 到 P99 的高度跨度为 `4.34 mm`；
逐帧法向相对平均法向的最大偏移为 `0.64 deg`。这说明深度与动态相机外参总体
连贯。另一方面，单帧拟合残差的 P95 中位数为 `14.18 mm`，因此不能把拟合面
当作无误差的标定真值；桌布起伏、传感器误差和配准误差的贡献尚未分离。

原始深度 AVI 的容器时间基准写成 15 fps、13.2 秒，而 RGB/GT 是 30 fps、
6.6 秒；两者都恰好有 198 帧。按同一帧号配对的平面残差中位数为 `3.63 mm`，
把深度第 i 帧配给 RGB 第 2i/2i+1 帧时反而升到 `8.36 mm`。因此当前样本应按
帧号配对；AVI 的 15 fps 标签不能被解释成只有一半的深度帧。没有采集时间戳，
所以这里仍不声称完成了严格的硬件时间同步认证。

## 为什么不能直接移动桌面

把发布的物体 GT 放到深度测得的承载面上比较，首帧 bowl 最低点低约
`15.78 mm`，plate 最低点低约 `22.21 mm`。但 GT 投影轮廓在 RGB 中基本贴合
真实物体，原始深度边缘也落在附近，不支持明显的外参方向或像素注册错误。

进一步用发布网格和 MANO 网格渲染相机 Z 深度，在无遮挡的 0、150、180、197
帧比较：

| 比较对象 | `原始深度 - GT 渲染深度` 合并中位数 |
| --- | ---: |
| 黑色 bowl/plate | `-5.50 mm` |
| 人手 MANO 表面 | `+5.33 mm` |

两类表面的偏差方向相反。这只能排除“给所有光轴深度统一加减同一个常数，
就让两个中位数同时归零”的办法，不能排除完整的刚体配准或其他标定修正。
不同材质的深度误差、网格与实物的差别、MANO 拟合误差、标注和配准误差都是
待验证的原因，目前没有证据把偏差归因给其中某一项。

当前 `T_sim_world` 的竖直平移，是把发布 plate 网格首帧最低点放到论文规定的
仿真桌面 `z=0.72 m`；它不是由真实桌面深度测出来的。原始深度说明现实承载面
与发布 GT 并不完全自洽，但没有给出论文未公开的物理 reset 方法。因此暂不改动
`z=0.72 m` 和当前 GT；这不意味着现有竖直变换已经通过标定。统一刚体移动手、
物体和桌面不会消除它们原本的相交，机器人初始状态是否合法仍需独立检查。
